# PR-134 — current mapper evaluation

## Scope and reproducibility

This evaluation was run against backend `origin/develop` at `d5f8ebc`, parser version 4, with the deterministic vector and classical-morphology backend. No ML model was loaded. The fixture generator produces an SVG and a separate JSON ground truth from a fixed seed.

Commands from the backend root:

```powershell
python -m venv structural-mapper/.venv
structural-mapper/.venv/Scripts/python.exe -m pip install -r structural-mapper/requirements-geometry.txt
$env:STRUCTURAL_MAPPER_DISABLE_ML='1'
structural-mapper/.venv/Scripts/python.exe -m pytest structural-mapper/tests -q --basetemp .pytest-tmp/run
structural-mapper/.venv/Scripts/python.exe structural-mapper/tests/support/generate_synthetic.py --count 3 --seed 321 --output .pytest-tmp/fixtures
structural-mapper/.venv/Scripts/python.exe structural-mapper/benchmark.py --repeats 3 --output .pytest-tmp/benchmark.json .pytest-tmp/fixtures/clinic_00321.svg .pytest-tmp/fixtures/clinic_00322.svg .pytest-tmp/fixtures/clinic_00323.svg
# Rasterize the same SVG fixtures to PNG, then benchmark the PNG files with the same command.
```

The pytest run passed **39 tests**. Four model-store tests initially errored because the managed Windows temp area would not create pytest numbered directories. Re-running with a repository-local basetemp passed all tests; this is an environment issue, not a mapper test failure.

## Results

The fixed seeds contain 16, 12, and 14 labeled rooms and the same number of ground-truth doors, respectively. Mapper output and median wall-clock time across three complete runs, including decode and payload construction:

| Seed | Format | Spaces found / GT rooms | Doors / GT doors | Components | Wall crossings | Outside walkable | Median seconds |
|---|---|---:|---:|---:|---:|---:|---:|
| 321 | SVG | 9 / 16 | 8 / 16 | 1 | 0 | 0 | 11.056 |
| 322 | SVG | 23 / 12 | 12 / 12 | 4 | 0 | 0 | 10.794 |
| 323 | SVG | 2 / 14 | 1 / 14 | 1 | 0 | 0 | 11.594 |
| 321 | PNG (1176 × 728) | 17 / 16 | 16 / 16 | 1 | 0 | 0 | 2.746 |
| 322 | PNG (1344 × 728) | 13 / 12 | 12 / 12 | 1 | 0 | 0 | 2.320 |
| 323 | PNG (1344 × 840) | 15 / 14 | 14 / 14 | 1 | 0 | 0 | 2.826 |

The SVG result for seed 322 is split into four graph components despite every edge passing the geometric containment checks. A validator status of `ok` therefore does not by itself mean every recognized room is connected. SVG seeds 321 and 323 substantially miss the labeled room/door topology. Rasterizing these exact fixtures improves counts and connectivity on this tiny sample; it does not prove PNG generally performs better because it changes the ingestion path and no held-out corpus was used.

## Interpretation and limitations

These counts are a small controlled smoke evaluation, not an accuracy estimate for real clinics. The generator draws rectilinear plans with explicit SVG lines and labels; it does not represent scan noise, furniture, irregular walls, ramps, multiple corridor shapes, or annotation ambiguity. No independent annotated clinic corpus was evaluated here. Timing is from one Windows machine and should not be used as a latency guarantee.

The mapper's current topology and geometric validation are useful safety checks, but the measured variation means generated candidates need administrative review. Next evaluation work needs a held-out, independently annotated set of vector and raster clinic plans, with room/door precision and recall, graph connectivity and route reachability, and correction effort measured separately.
