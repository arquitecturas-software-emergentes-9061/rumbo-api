# PR-40 / US-28 — Entrega de instrucciones para recuperar acceso

## Alcance

Completa la entrega pendiente; no reemplaza el ciclo de tokens de IAM ni crea endpoints nuevos.
IAM mantiene el digest en Redis, caducidad, uso único, invalidación de enlaces anteriores y revocación
de sesiones. Communications escucha `PasswordResetRequestedEvent` después del commit y envía un
correo de texto mediante SMTP. No persiste el enlace en las notificaciones IN_APP ni registra secretos.

Los contratos públicos existentes siguen iguales:

- `POST /api/v1/password-recovery/requests` → 202 sin cuerpo para toda solicitud admitida,
  incluida una dirección desconocida. La respuesta no confirma la existencia de la cuenta ni la entrega.
- `POST /api/v1/password-recovery/confirmations` → 204; un enlace inválido, vencido o usado produce 400.
- La nueva contraseña permite iniciar sesión; la anterior y las sesiones revocadas dejan de servir.

## Configuración y prueba manual

En desarrollo, el perfil `local` habilita la entrega y Docker Compose incluye Mailpit
([documentación SMTP](https://mailpit.axllent.org/docs/usage/sending-messages/)).
`mvn spring-boot:run` inicia los servicios habituales. Abre Web en `http://localhost:4200`, solicita
recuperación y consulta `http://localhost:8025`. Mailpit recibe el correo por SMTP local, sin enviarlo
a Internet. El enlace abre `/restablecer-clave?token=...`, ya implementado en Web.
Mobile permite solicitar instrucciones y pegar ese enlace en «Ya tengo un enlace».

Para un despliegue, configurar `RECOVERY_MAIL_ENABLED=true`, `RECOVERY_MAIL_FROM`, `RECOVERY_RESET_PAGE`
(URL HTTPS pública sin parámetros ni fragmento), `SMTP_HOST`, `SMTP_PORT`, `SMTP_USERNAME`,
`SMTP_PASSWORD`, `SMTP_AUTH=true`, `SMTP_STARTTLS=true`. No subir credenciales al repositorio.
Fuera de `local`, la entrega está deshabilitada hasta configurarla explícitamente.
La comprobación de salud SMTP sigue esa misma configuración: solo depende del servidor de correo
cuando el envío está habilitado. PostgreSQL y Redis siguen comprobándose en todos los casos.
Los tiempos de conexión, lectura y escritura están limitados a tres segundos, siguiendo la
[configuración de Spring Boot](https://docs.spring.io/spring-boot/3.5/reference/io/email.html).

Un fallo SMTP conserva la respuesta neutral y registra solo el identificador de la cuenta. No hay
cola ni reintento automático: el usuario puede solicitar otro enlace cuando el proveedor se recupere.
La prueba local acredita recepción SMTP; no acredita entrega de un proveedor externo o carpeta de entrada.

## Verificación

`PasswordRecoveryEmailIntegrationTest` usa PostgreSQL 17, Redis 7 y Mailpit reales: obtiene el token
del correo recibido, recupera cuentas CLINIC_ADMIN y PATIENT, inicia sesión con la contraseña nueva,
rechaza la reutilización y verifica ausencia de correo para desconocidos y transacciones revertidas.
`PasswordRecoveryDeliveryTest` cubre configuración inválida y fallo de transporte sin filtrar secretos.
Se conserva `PasswordRecoveryIntegrationTest` para revocación de sesiones, contraseña débil, bloqueo,
reemplazo del enlace e intentos inválidos. Los resultados de la ejecución final se registran al cerrar el incremento.
